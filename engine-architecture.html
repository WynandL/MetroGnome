Which feature uses which audio engine, and how the signals flow.

The big picture

The app has two independent audio worlds. The metronome world (a click producer plus an optional mic listener) powers the plain Metronome, Practice, Speed Trainer, and the Rhythm Game. The tuner world is fully separate: its own recorder and pitch stack, sharing nothing with the rest. A third piece, the Mic Self-Test, is not a runtime feature but the calibration source that the whole mic-timing system reads from.

Click producer (MetronomeEngine) Mic listener (RhythmDetector) Shared DSP (audio/dsp) Calibration / config Dead in production

Engine reference

MetronomeEngine

audio/metronome/MetronomeEngine.kt

Raw AudioTrack in STREAM mode, sample-accurate. Pre-generated click buffers. onBeat fires ~16ms before the audio write to keep visuals in sync.

Two live instances: shared (Metronome/Practice/Speed Trainer) and the Rhythm Game's private one.

RhythmDetector

audio/rhythm/RhythmDetector.kt

Mic capture wrapper (AudioRecord + AEC + FrameClock). Two modes via classifyClaps: spectral (ClapDetector) or the legacy amplitude path.

3 instances, all classifyClaps=true. Legacy mode now unused.

ClapDetector

audio/dsp/ClapDetector.kt

Tells the 1100Hz Classic click from a broadband clap via two band followers + integrated ratio. The reason mic mode locks the click to Classic.

Used by all 3 RhythmDetectors and the Mic Self-Test.

OnsetDetector

audio/dsp/OnsetDetector.kt

Amplitude/flux onset with a single refractory. The old time-suppression partner. Replaced everywhere by the spectral path.

Dead in production (only reachable via classifyClaps=false, which nothing sets). Left in place.

MicCalibration

audio/selftest/MicCalibration.kt

Read-only view over the self-test result. isActive = user opt-in AND eligible device. Carries device latency.

Single source of truth for all mic features.

Tuner stack

audio/tuner/ + audio/dsp/{FFT,PitchDetector,BiquadFilter}

Tuner (MPM+FFT), TunerCalibrator (loopback/reference), AmbientDetector (room profiling). Own AudioRecord.

Isolated. Shares only generic DSP helpers (FFT, BiquadFilter), no metronome/mic-timing code.

PerformanceBonus

points/PerformanceBonus.kt

Per-hit credit curve (TIGHT/LOOSE ms), outlier-robust session score, MIN_HITS gate. Maps timing to bonus Gnotes.

Used by Practice + Speed Trainer only. The Rhythm Game scores differently.

Shared DSP (audio/dsp)

FFT · PitchDetector · BiquadFilter · OnsetDetector · ClapDetector

Pure, deterministic, unit-testable building blocks. BiquadFilter is shared by ClapDetector and the Tuner.

The one place the two audio worlds touch (generic filters only).

Key facts & gotchas

✅ All 3 mic features are now spectral

Practice, Speed Trainer, and the Rhythm Game all run classifyClaps=true. The click is rejected by frequency, so an on-beat hit still scores (the old time window dropped those).

🎧 Classic click is forced when mic is on

Practice + Speed Trainer override the engine to Classic via setMicSoundOverride (saved sound untouched, restored in stopInternal). The Rhythm Game was already always Classic. ClapDetector is tuned to that click.

⚠ Speed Trainer has no engine of its own

It drives the shared MetronomeEngine through the bpmRequest collector in MetronomeScreen. So changes to the shared engine path affect both the plain metronome and Speed Trainer.

⚠ Two scoring systems, not one

Practice/Speed Trainer feed deviations into PerformanceBonus (Gnotes). The Rhythm Game uses its own PERFECT/GOOD/ALMOST hit windows. Do not assume a shared scorer.

⚊ OnsetDetector path is dead

Nothing constructs RhythmDetector() without classifyClaps=true anymore, so the amplitude + suppressUntilMs branch is unreachable in production. Candidate for future cleanup.

📊 Dev visibility: Mic Timing Log

All 3 features (Practice now included) log to MicDiagnosticsBuffer in dev mode. The CLICKS chip counts spectral rejections with band ratios = direct proof the filter is firing.
